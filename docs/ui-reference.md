# 手机 UI 采样与实现依据

采样日期：2026-11-15（Asia/Shanghai）。参考为通过 USB 实际操作的 Android ChatGPT 浅色界面；本应用保留 CCtunnel 的名称、功能和服务协议。

## 设备与采样方法

- 画面：1080 × 2400 px，密度 3 px/dp，布局宽度 360 dp，字体缩放 1。
- 使用 Android 截图记录稳定布局，操作结束后等待至少 1200 ms，避免把动画中间帧当成最终尺寸。
- 使用 Android `screenrecord` 录制实际点击、拖动、列表滚动、文字长按及菜单；以 PyAV 解码帧的 PTS 时间戳量测，不以文件平均帧率估计时长。静止画面可能只有稀疏帧，动画片段主要是约 16.7 ms 间隔。
- 原始截图和视频仅保存在本地 `.tmp/chatgpt-ui-reference/`，可能包含个人聊天和账户内容，不作为公开文档素材或提交到版本控制。本文件只记录通用界面参数。

## 真实交互观察

- 侧栏覆盖在聊天内容上，背后聊天不跟随平移；顶部标题/搜索和底部新建按钮/头像保持固定，中间列表可从它们下面滚动，边缘使用柔和遮挡渐变。
- 手指在侧栏中横向拖动时，面板跟随手指；释放后继续完成或返回。20 px（6.7 dp）/700 ms 左拖保留打开；120 px（40 dp）/700 ms 左拖关闭；600 px/1000 ms 左拖关闭。当前把距离阈值设置为 24 dp，位于实测的保持/关闭范围内，尚未二分测定原应用的精确阈值。
- 从 x = 75 px 开始右拖至 780 px（1000 ms）可展开侧栏。最外侧 x < 40 px 的一次手势触发 vivo 系统侧栏，该片段与 ChatGPT 无关，已排除。
- 长按普通回复正文会进入 Android 原生文字选择，保留选择柄和系统浮动操作条。
- 回复末尾“更多”打开位于消息附近的白色浮层；顶部有灰色时间信息，后续图标行和分隔线。它不使用底部全宽模态面板，也没有全屏黑遮罩。
- 账户头像进入设置；常规设置中的外观选择是锚定菜单。采样只打开、关闭菜单，未变更设置值。
- 新聊天在键盘出现和收起时保持输入胶囊紧贴键盘/系统导航区；实际捕获中偶尔出现顶部图标未及时重绘，后续触摸又恢复，这一渲染毛刺不作为目标行为。

## 动画量测

原始文件 `walkthrough-1.mp4` 的有效片段：

| 片段 | 帧时间范围 | 观察 |
| --- | --- | --- |
| 会话菜单退出 | 18.342–18.507 s | 约 165 ms 的淡出，并轻微朝右上锚点收缩；背景没有同步变暗 |
| 附件菜单进入 | 33.139–33.325 s | 约 186 ms 的主要显现过程；从左下锚点缩放、淡入，约 33.39 s 后已稳定 |
| 侧栏展开 | 71.516–71.735 s | 单调接近最终 864 px 边界，没有反向回弹或越过最终宽度 |

侧栏边界取画面 y = 1200 px 的亮暗交界。下列时间是视频时间，不能当作输入事件自身的时间戳：

| PTS / s | 侧栏右边界 x / px |
| --- | --- |
| 71.5157 | 515 |
| 71.5344 | 644 |
| 71.5508 | 729 |
| 71.5696 | 783 |
| 71.5844 | 816 |
| 71.6015 | 835 |
| 71.6182 | 847 |
| 71.6514 | 858 |
| 71.7028 | 862 |
| 71.7353 | 863 |

对这些可辨识边界拟合临界阻尼响应 `x = 864 × (1 - (1 + ωt) × exp(-ωt))`，得到约 `ω = 37.1`、刚度 `1376`，拟合边界 RMSE 约 1.73 px。时间原点同时拟合，故这个结果是实现近似，不是对参考应用内部动画参数的读取。`DeskMotion` 使用阻尼比 1、刚度 1400；保留手势速度交接、取消和中断处理。

锚定菜单单独使用进入 160 ms、退出 150 ms 的 opacity，缩放采用临界阻尼刚度 1300，初始约 0.8、退出目标约 0.94，并按菜单所在角设置缩放原点。底部模态面板保留独立的位移和遮罩状态，避免拖动时整个遮罩跟着面板移动。

补充视频 `interactions-2.mp4`、`interactions-3.mp4`、`settings-4.mp4`、`drawer-5.mp4` 分别记录侧栏/滚动、消息操作、设置选择菜单、极短拖动与长拖关闭。代码验证继续覆盖侧栏单调性、80% 最终宽度、动画中断、手势取消以及模态输入隔离。

补充真机采样 `reference-more*.png`、`reference-end.png` 和 `reference-load-more.mp4` 记录实际连续滚动。当前参考账户的列表滚到最早会话后不再移动，末尾没有可见的加载按钮；本轮没有据此推断 ChatGPT 的网络分页协议或精确批量数。按用户明确要求，项目侧栏在尚有未展示条目时提供“加载更多会话”，原地追加、保持滚动位置，展示全部后隐藏。

## 阴影动画全量审查（2026-11-15）

- 检索全部生产代码中的投影、透明度图层、Popup、圆角裁剪和进出动画。确认会话菜单、回到最新消息按钮、回复操作 Popup 有父透明度层裁切外扩阴影的路径；浮动图标按钮的启用透明度变化也存在同类复用风险。顶部胶囊、输入框的阴影不经过这些淡入淡出路径；侧栏、设置页及模型/权限/远程控制等底部面板没有同类外扩投影。
- Compose 1.7.6 的 Auto 透明度层按自身矩形大小建立离屏缓冲，故中间帧会截掉外部阴影。参考 [Android Graphics modifiers](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers)。修复为在透明度层四周实际预留 56dp，再补偿布局尺寸和位置；保留整体合成，避免逐项调透明度时阴影透过填色，形成内部条带或多边形。菜单位置、按钮大小与触摸目标保持不变。
- 新增 `DeskFloatingVisibility`，缩放和透明度注册到同一过渡，支持退出完成后卸载和中途反向。回复 Popup 另预留 48dp 窗口阴影空间，定位按可见菜单计算；透明留边点击可以关闭。首次打开未结束就关闭的早退条件加入 `isIdle`，避免收回动画被直接跳过。
- `ShadowRenderingTest` 使用合成纯色填充定位实际轮廓，按 32ms 间隔检查进入、退出、反向和禁用变化的外部阴影及圆角边界连续性，并检查纯色内部是否均匀。保留旧 Auto/fade 实现作为缺陷对照，确保检测能识别矩形截边；截图不使用真实会话。
- 最终构建、原生边界检查、79 个 JVM 单元测试和 Lint 通过。真机逐项通过 5 个阴影检测（共享过渡、会话菜单、返回最新按钮及中途反向、浮动按钮启用变化、旧缺陷对照）和 4 个回复菜单定位/留白点击/系统返回/快速开关检查。64ms 纯色示例帧透明度约 0.601、外部阴影仍连续，内部 RGB 极差为 0；人工复看菜单与圆形按钮中间帧没有矩形截边或内部叠色。
